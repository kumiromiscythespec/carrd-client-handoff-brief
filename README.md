# Carrd client handoff brief

A blank, editable plain-text brief for freelance Carrd page creators preparing client work. Use it to agree who owns, edits, pays for and checks the next version of a page.

- [Read or copy the TXT in this repository](./client-handoff-template.txt).
- [Open the hosted plain-text copy](https://page-scope-1109.crisp-llama-2628.chatgpt.site/client-handoff-template.txt).

## Use your own local copy

Save or copy the blank TXT, then edit it in a text editor. You may use and edit a local copy for your own project handoff. It is a planning document, not software, an online form, an account change, a contract or a completed transfer. No signup is needed to read the worksheet.

1. **Choose the method.** Shared editing keeps the existing owner; an ownership transfer changes the owner; static export delivers files for separately arranged hosting and functionality. Record separate actions if more than one is needed.
2. **Check four roles separately.** Fill the sections for the owner sharing access, transfer sender, invited Admin/Editor and transfer recipient. Mark unused roles N/A. Do not copy one account's subscription or responsibilities to every collaborator.
3. **Record capacity and actual features.** Check the whole account's existing and incoming sites, plus features the work requires, against current official conditions. Record the date checked. An invitation is not automatically an incoming owned site.
4. **Assign responsibilities and finish the checks.** Record billing, domain and connected-service control, renewal responsibilities, acceptance checks, unresolved items and follow-up. Use role labels; keep passwords, recovery codes, authentication links and personal contact information out. Share a completed brief privately, not in a public reply.
5. **Include the share-image handoff when needed.** Keep the approved edited PNG and source wording, a separate description/alt-text draft (not embedded in the PNG), the agreed folder label, content permission/ownership checks, approving/update/publishing roles, and the published-page and actual-share-preview check. Mark it N/A when no separate image is in scope; leave open checks unresolved.

The file does not grant access, connect to Carrd, execute a transfer or verify an account or plan. Static exports need separate checks for hosting and provider-dependent behavior.
